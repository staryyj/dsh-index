# 投标文件整册组装

## 一、标准章节顺序（象山/宁波市政项目通用）

```
1. 封面（按招标文件给定格式）
2. 目录（自动生成，含页码）
3. 投标函及投标函附录
4. 法定代表人身份证明 / 授权委托书
5. 投标保证金缴纳证明
6. 资格审查资料（营业执照、资质、安许、业绩、财务、人员证书…）
7. 技术标（施工组织设计 + 附表 1~4）    ← 暗标则单独成册
8. 资信标（投标人一般情况、近年财务状况、业绩、信用情况…）
9. 商务标（投标总报价封面、已标价工程量清单）
10. 招标文件要求提交的其他资料
```

**以招标文件第八章"投标文件格式"为准**，顺序必须与目录一致。

## 二、施工组织设计（技术标）结构

1. 工程概况与特点分析（含主要工程量表）
2. 施工总体部署（组织机构、施工段划分、总平面布置图）
3. 主要分部分项工程施工方案（含工艺流程图）
4. 质量保证措施（含关键工序控制点）
5. 安全文明施工措施
6. 进度计划与交通组织
7. 季节性施工与应急保障

## 三、暗标去痕流程（必做）

```bash
# 1) 文字层排查：公司名、人名、电话、LOGO 文字
# 2) 图片层排查：印章、签字、水印、图纸图签
# 3) 页眉页脚：公司名/项目名/LOGO
# 4) 文档属性：作者、单位、最后修改人
# 5) 转 PDF 后再查一次（避免 Word 域残留）
```

**检查方法**：docx 解包后 grep `word/document.xml`、`word/header*.xml`、`word/footer*.xml`；
PDF 用文本抽取 + 逐页截图人工看。

## 四、页码与目录

1. 正文页码从第 1 页起，封面不编码；
2. 目录用域（TOC）生成，**交付前必须"更新目录"**，否则页码是旧的；
3. PDF 合并后核对：目录页码 = 实际页码；
4. 图表编号连续（图 1、图 2…；表 1、表 2…），与正文引用一致。

## 五、多标段交叉检查

同一批项目（如 40/41/42）同时投时：

| 检查项 | 规则 |
|---|---|
| 项目负责人 | **不得为同一人**（各标段均要求"无在建工程"） |
| 专职安全员 | 不得重复 |
| 业绩 | 同一业绩可用于多个标段（一般允许），但要看限额要求 |
| 保证金 | 各标段分别缴纳，不能混 |
| 技术标 | 内容可复用，**抬头与工程量必须对应各自标段** |

> 用户已明确：每个项目按**单独投标**口径准备（资源各自配齐，不做"谁主投谁陪标"的安排）。

## 六、交付与命名

```
44-项目简称-技术标（施工组织设计·A3四页）.docx/.pdf
44-项目简称-附表.docx/.pdf
44-项目简称-投标文件（整册）.pdf
```

- 文件名带序号（与招标项目编号对应），方便对账；
- 同一项目 docx 与 pdf 同名，便于替换；
- 交付前跑一遍 `doc-render` 技能核对页数。

## 七、常见坑

| 坑 | 后果 | 预防 |
|---|---|---|
| 目录页码没更新 | 评委翻不到 | 交付前更新域 |
| 暗标里残留公司名 | 废标 | grep + 逐页看图 |
| 报价封面漏造价师签章 | 否决 | 对照 10.1 条款 |
| PDF 合并顺序错 | 编排混乱 | 按目录清单合并 |
| 文件过大（图纸） | 上传失败 | 压缩图片、拆分附件 |
