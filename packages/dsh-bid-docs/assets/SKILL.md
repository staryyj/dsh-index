# 投标方案自动生成（技术标 + 附表）

把「招标资料 zip」变成两套交付物：

| 交付物 | 版式 | 页数 |
|---|---|---|
| 技术标（施工组织设计） | A3 横版，小四宋体 1.5 倍行距，暗标 | **4 页** |
| 附表 | A4，4 张表 + 2 张图，结构固定 | **5～6 页** |

## 一、跑之前要确认的三件事

1. **招标文件版本**：zip 里常有原版 + `补遗一`（V2/V3/V4），**必须用补遗后的最高版本**；
2. **技术标页数**：招标文件里搜「技术标文件…N 页」，多数是 10 页上限（A3 四页稿远低于上限，安全）；
3. **是否暗标**：搜「暗标」，暗标稿**不得出现单位名称、人员姓名、签章**，封面/页眉页脚要干净。

## 二、两个命令

```bash
# 1) 资料解析：解压、找最新招标文件、抽参数、汇总清单量
#    --name 建议传项目全称（zip 文件名即可），否则自动识别可能受 PDF 文本乱序影响
python scripts/run.py inspect --archive 项目包.zip --work work/项目名 \
    --name "象山县……工程三标段（……道路改造工程）"

# 2) 出稿：按 plan.json 生成图 → 技术标 → 附表 → PDF 并报页数
python scripts/run.py build --work work/项目名
```

`inspect` 产出：

| 文件 | 内容 |
|---|---|
| `work/params.json` | 工程名称、工期、建安造价、长度、宽度、保证金、资质、技术标页数、是否暗标 |
| `work/params.md` | 上面内容的可读版（先给用户看这个） |
| `work/boq.json` | 清单主要工程量归类汇总（拆除/水稳/沥青/人行道/管/井/排管/绿化…） |
| `work/tender.txt` | 招标文件全文（后续查否决条款、评标办法用） |
| `work/pages/*.png` | 封面/公告/前附表页面图：**工期、造价、长度的最终核对以此为准** |

`build` 读 `work/plan.json`；没有时自动生成草稿并提示补充。

## 三、plan.json 字段

```json
{
  "tag": "40",
  "short": "城西路",
  "name": "象山县……三标段（城西路（西街至丹峰路）道路改造工程）",
  "road": "城西路（西街至丹峰路）",
  "start": "西街", "end": "丹峰路",
  "length": 1257,
  "width_text": "14～20",
  "days": 360,
  "money": "2028.0871",
  "kind": "road",
  "struct": "沥青混凝土路面（局部水泥混凝土路面）",
  "scope": "道路工程、给排水工程、……、绿化工程",
  "start_date": "2026-12-20",
  "boq": { "沥青混凝土面层": { "m2": 26935.24 }, "...": {} },
  "qty_rows": [["1", "拆除路面", "m²", "14,269.90", "含切割、外运"]],
  "gantt": [["施工准备", 1, 40]],
  "equip": [["1", "履带式挖掘机", "PC200", "4", "日本", "2021", "103", "1.0m³", "路面破除"]],
  "labor": [["机械操作工", "10", "18", "16", "18", "12", "8"]],
  "land": [["项目部办公及仓库", "200", "道路中段", "第1～360天"]]
}
```

- `kind`：`road`＝新建/改扩建沥青路面；`blacktop`＝旧混凝土板加铺沥青（白改黑，自动切到病害处治/植筋/防裂贴/应力吸收层方案与专用横道图）；
- `qty_rows` 缺省时自动取 `boq` 汇总前 10 项；
- `equip`/`labor`/`land`/`gantt` 缺省时用内置市政道路标准配置（24 台设备、11 工种高峰 110 人、1710㎡ 用地）。

## 四、生成规则（不要改）

1. **工程量必须来自清单**（`boq.json`），不许按长度×宽度估算；
2. 附表**结构不变**：表1 25×9、表2 13×7、总平面 1×1、临时用地 8×4；只换单元格文字和两张图；
3. 进度横道图按 `references/横道图制图标准.md`：整月等宽、首末月按实际天数缩窄（最窄 22%）、年份条带居中、**只写计划开工+工期，不写计划竣工**、2600px/300dpi；
4. 技术标正文顺序固定：一 工程概况与特点（含工程量表）→ 二 总体部署（含总平面图）→ 三 分部分项方案（含流程图）→ 四 质量 → 五 安全文明 → 六 进度与交通 → 七 季节性与应急；
5. 生成后必须报**页数**（技术标 4 页、附表 5～6 页），页数变了要调 `K` 参数而不是删章节。

## 五、出稿后的自检

- [ ] 技术标 4 页、附表 5～6 页
- [ ] 项目名称、长度、宽度、建安造价、工期与招标文件一致
- [ ] 工程量与技术标工程量表、清单三者对得上
- [ ] 附表一设备与正文「主要施工机械」段落型号台数一致；附表二高峰人数与正文一致
- [ ] 暗标：无单位名称、无人员姓名、无签章、无页眉页脚残留
- [ ] 横道图无计划竣工日期、年份居中、首末月宽度有差别

## 六、常见问题

| 现象 | 处理 |
|---|---|
| `inspect` 找不到招标文件 | 文件名不含「招标文件」；手动指定或用 `--archive` 指向解压目录 |
| 清单量全是 0 | 该 xlsx 是「计算规则」或「通信清单」；改传主清单（名字含 清单/控制价） |
| 页数多 1 页 | 调 build 里的 `K`：`qty` 减行、`qu/sf/cv/pg/tf` 减条数、`s7` 3→2 |
| PDF 转不出 | 设 `BIDDOC_NODE` / `BIDDOC_LO_CLI` 环境变量，或改走 `soffice --headless` |
